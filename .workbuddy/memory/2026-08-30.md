## v0.6.0（ADR-0008 漂移裁决：intent/trace 桥接主链路）
- 用户质询「DSH 作为 agent runtime 是不是 PRD/PLAN 设定」——查实 PLAN T-P1-5 明文要求接入 `ctx.agents.followup`，实际直连且无裁决 = 漂移成立；更深发现：intent/trace 挂 `agent/pre-step`，该事件只有 dsh AgentLoop 才发 → **主会话上两个 PRD 亮点一直是死挂点**。
- 裁决（ADR-0008 + conflicts C6）：followup 是 fire-and-forget inbox 驱动（dsh runtime-types L124），与 Electron IPC 请求-响应不同构；v1「挂点桥接」= `dsh-runtime.firePreStep()` 每回合驱动 waterfall（`ctx.waterfall(event, payload, baseline)`，真实 cordis 实测可用），reject 硬拒不调模型；AgentLoop 全量事件化列 P7 路线图。
- fail 边界：runtime 未启动/waterfall 异常 → 放行 + WARN（基础设施缺失≠风险放行，执行侧沙箱白名单兜底）；仅 iter=0 门控用户意图一次。
- 验证：model-loop O1（`rm -rf /` → 0 次模型调用 + 拦截提示落盘）；verify 319/319；audit 0 issues。PLAN T-P1-5 / current-state 事实 7 已按 ADR 口径修正。
- 经验：**读插件挂点要问「这个事件谁发」**——挂在不驱动的事件上等于没挂；同类问题以后排查时先 grep 事件 emit 方。
