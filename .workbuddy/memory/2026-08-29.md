### T1 BUG-014 工具调用稳定化（最高优先级）

- **真根因（前序三轮都没找到）**：`runAgentTurn` 里
  `toolCalls.push({ name, arguments: { input: match[2] } })` —— 把整个 args 塞进 `input`
  字段，而 `executeTool` 读的是 `args.path` / `args.command`，**工具必然执行失败**。
  不是「模型格式不匹配」，是参数构造错误。
- 新增 `apps/desktop/agent-runtime.ts`：**纯逻辑、零 electron 依赖、可 node 直测**。
  承载 `TOOL_DEFS` / `parseToolArgs` / `normalizeNativeToolCalls` / `extractToolCalls` /
  `buildAssistantToolCallMessage` / `buildToolResultMessage` / `buildSystemPrompt`。
  `main.ts` 只保留需要 electron 的 `executeTool`。
- `callModel` 改返回结构化 `ModelReply{content, toolCalls, source, toolsRejected}`，
  **消除「tool_calls → `<tool:>` 文本 → 正则解码」的往返断点**。
- 原生 `tool_calls` **全部**执行（旧实现只取 `[0]`）；统一 OpenAI / Ollama / 摊平三种形态。
- 工具结果回传：原生模式 `role:'tool'` + `tool_call_id`；文本兜底模式 `role:'user'`
  （assistant 消息无 tool_calls 时发 `role:'tool'` 会被网关判非法）。**不再用 `role:'system'`**。
- 网关降级：`tool_choice`/`tools` 被拒（400/404/415/422）逐级重试（完整 → 去 tool_choice →
  去 tools），成功后置 `toolsRejected`，本轮转文本兜底，避免每轮重试三次。

### T2 BUG-013 数据持久化路径隔离

- 新增 `dataDir()`：`ORCHDESK_HOME` > 便携模式（exe 同目录 `orchdesk-data`，需已存在或
  exe 旁有 `PORTABLE` 标记）> `%APPDATA%/OrchDesk`。
- **NSIS 的 userData 本身即 `%APPDATA%\OrchDesk`，故 portable 与 NSIS 天然共用同一目录**，
  满足「至少保底 portable 和 NSIS 同目录」要求。
- `migrateLegacyData()` 启动迁移：扫描全部历史候选目录，会话按 id 取 `updated` 较新并
  合并消息，模型按 provider id 合并；**只补齐不覆盖**。
