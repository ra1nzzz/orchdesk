## 「执行启动预览」实拉验证 → 环境级阻断（BUG-W02）
- 用户指令「执行启动预览」，实际拉起 Electron 桌面壳。排错链逐层排除：
  1. tsc 编译 `dist/main.js` 原为 ESM（`module:ESNext`+`"type":"module"`）→ Electron cli.js 用 Node 加载触发 `cjsPreparseModuleExports` 崩溃；改为 `module:commonjs` + 去掉 `"type":"module"`，重建 CJS（EXIT=0）。
  2. CJS 后仍崩溃 `require('electron')` → undefined：解析到 npm 包 `index.js`（`module.exports = getElectronPath()` 返回 exe 路径**字符串**，非内置模块对象），解构 `app` 失败。
  3. `require.resolve('electron')` 解析到 npm 包；干净目录 `require('electron')` → MODULE_NOT_FOUND；`process._linkedBinding('electron')` → "No such binding was linked"。
  4. `electron.asar` 缺失为**误判红线**（官方 zip 仅含 `default_app.asar`，内置模块编译进二进制，无 electron.asar）。
  5. `--version` 返回 `v22.19.0` 为**正常行为**（Electron 36 绑定 Node 版本），非缺陷。
  6. v33 对照 `NODE_OPTIONS=--use-system-ca is not allowed` → 用 `env -u NODE_OPTIONS` 重测，v33 与 v36 **同样** MODULE_NOT_FOUND，排除 NODE_OPTIONS 污染。
  7. 官方 GitHub 下载副本（121629456B）对照 → 同样 "No such binding was linked"，排除镜像损坏。
- **最终根因**：Electron 内置 `electron` 模块在本运行时对所有版本（v33/v36）均**未链接**，任何 Electron 应用（含 default_app）在本机都拿不到 `app`/`BrowserWindow` 等内置对象。判定为**运行环境级阻断**（非代码缺陷 / 非镜像损坏 / 非版本 / 非 NODE_OPTIONS）。
- **结论**：即便有显示器也无法在本机启动 GUI 预览；须转移到可正常运行 Electron 的机器执行 `pnpm --filter @orchdesk/desktop start`。Electron 二进制本身完整（202MB、exe 可执行、version 探测 exit 0）。
- **文档落地**：current-state.md 阶段段 / 「已完成(P1)」表 / 验证门控段 / 下一步 全部改为如实反映「本机运行时无法链接 Electron 内置模块（环境级阻断）」；60-BUG 新增 BUG-W02 登记（含根因与误判澄清）。

## T-P2-3 TRACE 脱敏遥测真实逻辑实现（2026-08-18 深夜续）
- **用户指令**：「继续」→ 按 P2 顺序执行 T-P2-3，遵循原文档设定不漂移。
- **设计溯源**：T-P2-3（PLAN.md L228）/ PRD.md L184 / ui-ux.md L95 + 防漂移 4 条（PLAN.md L241-245）。渲染层 TRACE 按钮 UI + 点击 toast 已在 P1 就绪（app.js L145-146、L663），但此前点击只做本地 state.feedback.add + toast，未真正驱动后端脱敏上传——T-P2-3 补真实后端。dsh 事件清单无「Loop 结束」专用事件（有 agent/pre-step/request/error/status、session/event 等），故 Loop 结束用户反馈用导出 API recordFeedback 作为事件驱动落点。
- **实现**（`packages/plugin/trace/src/index.ts` 由骨架升级）：
  - ① `agent/pre-step` 每 turn 起始（step===0）观测语用意图标签（保守分类 read/write/exec/network/message/query/other），**不记录消息原文**（防漂移④）。
  - ② `mask()` 真实脱敏：白名单字段 + `sessionKey`/`messageKey` djb2 哈希（不泄露原始 session/agent id 形状），根源杜绝路径/凭据/PII 上传（防漂移①）。
  - ③ 内存离线队列 `pending` + 失败重试队列（指数退避，最多 5 次，超限丢弃单条），上传失败不阻塞会话（防漂移②）；导出 `queueSize()` 可观测。
  - ④ GitHub REST 上传 seam（`fetch`，无额外依赖，octokit 可在 dsh 依赖层替换）；`repoUrl` 用户配置不硬编码（防漂移③）；token 取 `config.token` / `ORCHDESK_TRACE_TOKEN` env，**绝不**进日志/payload（仅记状态码）。
  - ⑤ 导出 `recordFeedback(intent,feedback,sessionKey?,messageKey?)` 供桥/渲染层 TRACE 按钮调用，作为 Loop 结束用户反馈真实落点；`flush()` 供 dsh 生命周期结束调用。
- **结果**：`tsc -p packages/plugin/trace/tsconfig.json --noEmit` **EXIT=0**（修正 2 处：UserMessage 改从 dsh-session 导入；batch[0] 在 noUncheckedIndexedAccess 下用 `?.ts ?? ''`）。
