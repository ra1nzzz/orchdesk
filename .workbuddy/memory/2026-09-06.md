## Skill 发布到本地（零依赖 ZIP 打包器）

### 关键发现：.skill 真实格式
反推本机真实 .skill（promo-video.skill 等）：**ZIP，根目录 = `<slug>/SKILL.md`**（不是
SKILL.md 在 zip 根！），可含 references/ scripts/ 子目录。SKILL.md 顶部 YAML frontmatter
（name/description）`---` 分隔，其后正文。应用内 **.skill 从不被解压执行**——是分发产物，
只做管理（列/删/上传观雅集）。

### skill-pack.ts（纯逻辑，零依赖 STORE zip + CRC32）
不引 adm-zip/jszip（违背零依赖纪律）。STORE（无压缩）+ CRC32（多项式 0xEDB88320）。
输出用**系统 python zipfile 跨语言读回**验证通过（中文/特殊字符保留、testzip 无坏条目）——
手写 zip 最大风险是「自己写自己读都对、别人读不了」，跨语言校验必须做。

### guanji.publishLocalSkill(slug,description,body)
打包 <slug>/SKILL.md → 数据目录 skills/<slug>.skill（临时文件+rename 防半截）。UI：
插件页技能市场加「+ 发布技能到本地」按钮 → 表单(slug/描述/正文) → bridge.publishLocalSkill
→ refreshInstalledSkills。IPC orchdesk:skill-publish-local + preload 桥。

## 连接器自动发现（本地 CLI 登录态）

### connector-discover.ts（纯逻辑）
- parseGitCredentials（~/.git-credentials 行解析 host/user/pass）
- findGithubFromGitCredentials（挑 github.com）
- parseGhHosts（gh hosts.yml oauth 账户，仅作「已登录」信号）
- discoverConnector(github)：git-credentials 明文优先 → gh hosts 备用（token 混淆不可读，
  诚实返回 usable=false + 提示 `gh auth token`）
- 其它连接器（linear/notion/飞书…）本机无标准 CLI 登录态 → 诚实返回「无」，不硬凑

### 诚实性设计
自动发现 ≠ 自动写入：只「找到」secret 回填表单，用户点「保存并测试」才落盘（尊重授权）。
UI 只给 github 显示「自动发现」按钮（其它不展示假按钮）。IPC orchdesk:connector-discover。

### 实机验证发现（重要）
本机 ~/.git-credentials 有**两条** github 凭据，parser 取第一条 = 过期的 x-access-token
（就是 git push 时遮蔽有效 token 的那条！）。发现能命中但可能回填坏 token —— 安全网是
「保存即探测」：保存后真实 GitHub probe 会 401，让用户知道。诚实预填 + 探测兜底是对的，
无需特判。已把此 caveat 记入长期记忆。
