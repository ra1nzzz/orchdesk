### 踩坑：EBUSY asar 句柄泄漏（新，之前没记过）
- 现象：`kill-running.cjs` 报「无运行中的 OrchDesk 进程」，仍 `EBUSY: unlink .../app.asar`，删除/改名/等 30s 全不行。
- **根因：electron-builder 报错后进程不退出**（`npx electron-builder` + `cli.js` 两层 node 都挂着），持续持有刚写入的 asar 句柄 → 此后所有重试被同一句柄拦死。
- **解法：换全新输出目录** `-c.directories.output=release-v0130-r1`。同目录重试 5 次全失败，换目录首次即通过（1 分钟）。
- 排查必须按**命令行**找进程（都叫 node.exe，按进程名找不到）：`Get-CimInstance Win32_Process | ? CommandLine -match electron-builder` → `Stop-Process -Force`。
- 别误判成沙箱拦截：同目录「新建文件再删除」成功 = 目录无保护，是**特定文件**被锁；与后缀、大小、目录位置均无关（逐一对照验证过）。
- 附带：直连 GitHub 取 nsis/winCodeSign 约五成概率 TLS 断连 → 循环重试兜住。

## BUG-022 修复（实机冒烟首批反馈）

- **现象**：用户实跑 v0.13.0-r1 发现——新建项目绑定 D 盘目录后，项目 ··· 菜单「打开项目目录」弹出的是 C 盘 `%APPDATA%/OrchDesk` 数据目录。
- **根因**：`orchdesk:open-project-dir` handler 恒 `shell.openPath(dataDir())`，注释「项目目录 = userData」是早期概念混用遗留；项目对象 `path` 字段有写入方、无读取方（渲染层早已用 `p.path` 渲染图标）——死挂点变体。e2e 之前测不到：bridge mock 无条件返 ok + 种子项目不带 `path`。
- **修复**（main.ts / preload.ts / renderer/app.js）：handler 接受可选 `projectPath`（有绑定 → statSync 校验目录真实存在 → 开绑定目录；无绑定 → `{ok:false, reason:'该项目未绑定本地文件夹…'}`）；`shell.openPath` 返回值不再被吞（成功返回 ''）；渲染层传 `p.path` + toast 回显实际路径；顺手修同族 `open-log-dir` 吞失败返回值。
- **验证**：e2e 新增 6 条断言（152→158，mock 用 `window.__openedPath` 逐调用记录参数），verify **24 套件 820 项全绿**，tsc EXIT=0，审计 0 issues。
- **文档**：60-BUG 归档 BUG-022（v0.13.1 pending）、CHECKPOINT 第十九批、release.md +v0.13.1（pending）段、current-state 下一步更新。
- **教训**：mock 太宽容（无条件 ok、种子数据缺字段）会让「传参错误」类死挂点测不出来——回归断言要让 mock 逐调用记录参数。
