## P0 落地：TS 直测 loader + 架构守护测试（commit a17d9cd，ADR-0010，verify 674→702 / 20 套件）
- **零依赖 TS 直测 loader**（`apps/desktop/scripts/ts-loader-hooks.mjs` + `ts-load.cjs`）：基于 **Node 22.13+ 内置 `module.stripTypeScriptTypes()`（amaro/swc）+ ESM `module.register()` hooks**，没装 esbuild/ts-node（零安装失败风险、零供应链面）。
  - 关键实现点：① CJS loader **不认 .ts 扩展名**（`require('/x.ts')` 直接 MODULE_NOT_FOUND，加 `--experimental-strip-types` 也没用），必须走 ESM `import()` + hooks；② hooks 里 `load` 用 `new URL(url).pathname` 判断后缀（而非 `url.endsWith('.ts')`），才能支持 `?t=N` cache-busting；③ resolve 要先剥 `?query#hash` 再探磁盘、命中后原样拼回；④ 只接管 `.ts`，`.js/.json/.node` 交回 `nextResolve/nextLoad` —— 因此 **stub electron 的 `Module._load` 钩子 + require('dist/main.js') 完全不受影响**（有回归用例守护）。
  - 我们的 TS 源码正好满足 strip 约束：无 enum / namespace / 参数属性 / 装饰器，纯逻辑模块只 import node 内置 + 无扩展名相对路径。
- **一致性硬约束**：`ts-loader-verify.cjs` B 组断言「同一输入 TS 版与 dist 版输出逐 JSON 相等」，否则 loader 引入语义漂移 → 直测结果不可信。C 组证明收益：覆写 fixture 源码后不跑 tsc，断言立刻读到新值。
- **架构守护测试**（`arch-guard-verify.cjs`，15 项）：R1 渲染层禁 Node/Electron / R2 纯逻辑零 electron / R3 纯逻辑不依赖宿主层 / R4 渲染层不持久化不执行工具 / R5 禁硬编码本机路径与密钥 / R6 插件产物链路不陈旧（src→lib→vendor）/ R7 套件必须在 verify 链上。
  - **元规则自检（Minke knownViolation 思路，最关键）**：M1 每条规则必须命中自己的正样本（抓不到 = 规则失效 FAIL）、M2 扫描面非空（glob 写错 = 规则空转 FAIL）、M3 白名单文件须存在、M4 白名单确实零 electron。理由：架构规则是**否定式断言**，失效时静默通过——比没规则更危险（虚假安全感）。
  - 扫描前剥离块注释与整行 `//`（不剥行尾，免误伤 `http://`），否则 session-fork.js 注释里的 require 示例会误报。
- **R6 当场抓到真陈旧**：compensation / evolution / multi / prompt 四个插件 `src` 比 `lib` 新（正是记忆里「改插件源码忘了 tsc+vendor 跑出假结果」那个坑）——已重编译 + vendor 修复。**这就是机器守护的价值：人肉纪律会失效。**
