## 补充需求：技能与MCP → 「能力」（2026-09-05 深夜）

用户一句话：「技能与MCP改成：能力，包含使用中的插件、技能、MCP」。

### 改名之外：两个分组都不是真数据源（旧 TAB 名不副实）
1. **插件（默认启用）** 的数据是渲染层硬编码常量 `['intent','trace','brain','multi']`，
   与运行时装载无关 → 改取 `state.pluginRuntime.plugins` 真实装载。
   运行时未接入时回落声明清单 + 显式标注「运行时未接入 · 非实时装载状态」，
   不用空列表冒充「没有插件」（「未接入」≠「为空」第三次踩到）。
2. **技能** 从 Agent 消息正则抓 `{skill:xxx}` —— 而 `{skill:xxx}` 是**提示词模板**的引用语法
   （`vendor/plugins/prompt/index.js` 的 `extractSkillRefs` 消费，未解析输出 `«skill:xxx:unresolved»`），
   Agent 回复里**根本不会出现** → 恒为空，典型死挂点。已删。
   改取磁盘真实扫描：`guanji.ts` 新增 `listInstalledSkills()`（扫 `数据目录/skills/*.skill`，
   slug 再过 `isMarketDirName` 白名单）+ `uninstallSkill()`（真删文件，slug 同样过白名单防穿越）；
   新 IPC `orchdesk:skills-installed` / `orchdesk:skill-uninstall` + preload 桥 +
   渲染层 `refreshInstalledSkills()`（合并保留内存启用开关）。
   **此前 `state.installedSkills` 只在安装时 push 进内存数组，重启即清零（磁盘有包却显示 0 个）；
   `skill-uninstall` 也只从数组移除，文件还在。**
3. 未接入 vs 「已扫描但没装」分开：标题「技能 · 未接入」/「技能 · 使用中 N/M」，
   不把「没读到」说成「读到了 0 个」。
