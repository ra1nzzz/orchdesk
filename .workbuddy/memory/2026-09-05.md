## MCP 真接入（2026-09-05 夜，用户裁决「真接入」）

前一轮排查发现「能力」TAB 的「MCP 连接」分组是**唯一残留的 mock**——4 个条目名
filesystem/intent/memory/orchestration 写死，全仓无真实 MCP 实现，仅把「连接状态」
映射到插件装载状态冒充连接列表。这是 P1-4「清 mock」时的半截清理（EXPERTS/TEAMS
改了动态源，mcps 漏改）。

### 方案：零依赖手写 stdio 客户端
不引 @modelcontextprotocol/sdk（会带进 zod/transport 依赖树，违反「零依赖、纯逻辑
可直测」纪律）。MCP 核心就是 JSON-RPC 2.0 over stdio，三个 method 足够。

`mcp-client.ts`（纯逻辑、零 electron）：
- initialize → notifications/initialized → tools/list → tools/call
- spawn 时 env 剔除 NODE_OPTIONS/NODE_PATH/ELECTRON_RUN_AS_NODE（同 terminal-pty 铁律，
  防本机 safe-delete shim 注入子进程崩掉 MCP server）
- 握手/列工具/调工具各自独立超时（INIT 15s / LIST 15s / CALL 120s）
- 配置归一化：id 走 isMarketDirName 白名单防路径穿越、args≤64、env≤32
- 序列化/解析容错：坏条目丢弃计数，整段坏 JSON ok=false 不抛异常

接线：
- 配置存 数据目录/mcp.json（DATA_FILE_NAMES.mcp 新增，随目录迁移）
- env 值 encryptSecret 加密落盘 / decryptSecret 回显（同凭据纪律）
- 主进程 6 个 IPC：mcp-list/save/delete/set-enabled/probe/call-tool
- preload 桥 + 渲染层：插件页加「MCP」管理区（添加/探测/启停/删除，保存即握手），
  「能力」TAB 的 MCP 分组读真实 server（已连接/连接失败/已停用三态 + 工具数）

三态分离纪律：「未配置」≠「配置了连不上」≠「连接成功但无工具」。

## UI/UX 优化（ui-ux-pro-max SKILL，2026-09-06）

用户用 @skill:ui-ux-pro-max 启的优化任务，要求克制收敛、四个面（软件 UI 总览 / 设置页 / 插件&SKILL 搜索增删启用禁用删除 / 会话主界面）。

### 改动总览（仅前端，tsc 无改动）

1. **对比度（P1 /colorize）** —— `--fg-faint` 双主题全部过 WCAG AA：
   - dark `#6B7280` → `#8A93A3`（bg 5.38:1，panel 4.95:1 PASS）
   - light `#9CA3AF` → `#667085`（bg 4.97:1，panel 4.56:1 PASS）
   - `--fg-dim` 也微调：dark `#9CA3AF`→`#A6ADBB`、light `#6B7280`→`#5F6B7A`（均 ≥5.4）

2. **键盘可达（P1 /harden）** —— `hardenActions(root)` 在 render() 后给所有非原生
   可交互的 `[data-action]` div 补 `role="button" tabindex="0"`，跳过已有 role 的
   （如 .switch 的 role="switch"）和原生控件。委托层一次性收敛（取代逐个补），
   配合 focus-visible 选择器扩展，所有 div 交互元素键盘可达且焦点样式可见。
   body 级 keydown 把 Enter/Space 映射到 `[data-action][tabindex]` 的 click。

3. **硬编码色收敛（P2 /normalize）** —— `--term-bg` / `--term-fg` / `--diff-add-bg|fg`
   / `--diff-del-bg|fg` 显式 token；terminal/file-edit-error/.badge.warn 改用 token。
   xterm theme 配置（app.js:2876）保留字面色（JS 端取 CSS var 不便），但与 token 值一致。

4. **插件页搜索（新增前端功能）** —— `#plugSearch` 即时过滤内置插件卡片（名称/描述/能力/标识）。
   实现细节：所有卡片一次渲染（data-search 预拼小写），input 事件运行时切换 .style.display，
   **不触发 render()**（保输入焦点）。渲染后由 plugSearchFilter() 同步可见性。
   + 命中计数 `#plugSearchCount`，+ 空态提示 `#plugSearchEmpty`。

5. **技能市场搜索（新增前端功能）** —— 同套路：`#skillSearch` 过滤观雅集 skill 行。
   + 已安装技能清单重写为 `.is-row` 卡片（status badge + 体积 + 启停/卸载），卸载按钮
   染成 danger 弱色（`.btn.ghost.danger-text`），视觉与全局一致。

6. **设置页导航（信息架构轻改）** —— 7 项改为 `.settings-nav-item`（icon+label 统一行高），
   active 态改用 class 而非 inline background（与全局 token 同步），首次进入设置页
   默认高亮第一项。

7. **响应式保护（P3 /adapt）** —— body `min-width:700px`；<900px 自动收起任务监控/浏览器侧栏。

### 教训
- 输入框"实时过滤"一定不要触发 render()（会丢焦点）；用 data-search 预计算 + 运行时
  style.display 切换是无构建成本的最稳方案。
- 对比度修一个 token 可能牵连多处副作用（如 --fg-faint 被 67 处 10-11px 小字用），
  必须用相对亮度公式重算每对 fg × (bg/panel) 的 AA 比，浅色主题的 panel 对比度往往是
  瓶颈（不是 bg）。
