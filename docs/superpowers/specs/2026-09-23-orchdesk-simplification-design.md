# OrchDesk 简化&优化方案（C 混合 · 参考 ZCode）

- 日期：2026-09-23
- 状态：已批准，待实施
- 参考：zai-org/ZCode（Z.ai coding agent harness，6.3k stars）——一个 `zcode` 命令 = TUI/Web/Desktop 三入口共享同一 Agent 运行时；workspace 即当前目录；内置 provider 配置开箱即用；配置仅三五个环境变量
- 决策路径：C（轻默认 + 编排按需深化，原有功能 UX 继续调研优化）→ A（模型内嵌配置 + Ollama 自发现，演示模式兜底）→ A（ZCode 式单栏默认）→ A（隐式 cwd，项目降级为可选归档）→ A（单 spec 两阶段）

## 1. 背景与问题

**目标体验断点**（现状首 run 路径）：安装 → 2 步向导（第 2 步还要选默认专家）→ 欢迎页 → 发现没配模型 → 去设置页填 6 字段表单（类型/名称/URL/协议/KEY/模型）→ 面对四列界面（60/270/1fr/300）+ 项目/任务/分叉/记忆四域/授权三模式/L0-L4/白名单/补偿层一整套概念。向导第 1 页自己写着"打开就是会话……在后台安静运行"，但执行层没有兑现这个承诺。

**重量来源**（按摩擦排序）：

1. 配置前置：模型提供商是 6 字段设置页表单，不配不能聊
2. 结构前置：新会话先问"放哪个项目/任务"
3. 布局常宽：四列同屏，rail+侧栏+右栏全部默认展开
4. 概念前置：专家选择、三模式、L0-L4、白名单、补偿层首日即曝光
5. 静默失败：网络白名单空 = 全拒，用户看到的是"没反应"而非"需要授权"

**ZCode 的对应解法**：一个入口（输入框）开始；workspace=cwd 无需前置结构；内置 provider 配置；一个运行时多表面；按需深化。

## 2. 目标 / 非目标

目标：

- 默认形态 = 打开即用的 coding agent（ZCode 式单栏 + 隐式 cwd + 内嵌模型配置）
- 编排能力（项目/任务/专家团/分叉回放/记忆/任务监控）完整保留，按需展开为"项目模式"
- 原有功能 UX 逐 surface 调研优化（第二阶段，与第一阶段交织）
- 本地优先、数据不出本机、风控 fail-closed 底线——全部不变

非目标（YAGNI）：

- 不做 TUI/CLI 第三入口（ZCode 有三入口；OrchDesk 本方案只做桌面，CLI 留作未来）
- 不删任何现有功能、不改主进程与插件架构、不动风控三模式/模型链路/vendor 产物
- 不引入账号体系/云同步

## 3. 设计原则

**先聊起来，结构自然沉淀；重的按需出现，轻的是默认。**（对齐 ZCode：one entry, one runtime, depth on demand.）

## 4. 方案 C 总体形态

```
                轻模式（默认）                     项目模式（按需触发）
┌─────────────────────────────┐      ┌──────────────────────────────────┐
│ 会话列表(可折叠) │  聊天区    │ 触发 │ 会话列表 │ 聊天区 │ 任务监控(常驻) │
│                 │           │ ───► │          │        │ 专家团/分叉入口  │
│  模型chip内嵌    │  composer │      │          │        │                │
└─────────────────────────────┘      └──────────────────────────────────┘
   导航收起(Ctrl+K/图标)                  rail/导航恢复，编排入口就位
```

触发条件（任一）：用户主动建项目/任务；Agent 产出多步 `orch-plan` 计划；引用专家团/派发任务。触发后展开重形态；用户可手动回落轻模式。

## 5. 轻模式（默认形态）详设

### 5.1 布局：单栏 + 按需面板

- 默认 grid = 会话列表（240px，可折叠为 0）+ 主区（1fr）；**去掉 rail 与右栏的默认展开**
- 导航：Ctrl+K 命令面板/角落图标唤出导航抽屉（会话/插件/设置），轻模式下不常驻
- 右栏任务监控：从"设置页常驻"改为**回合中自动浮出**——Agent 产出 `orch-plan` 或工具步骤时从右侧滑出，回合结束 5s 后自动收起（用户可钉住）；这同时是项目模式的天然触发之一
- 浏览器/终端/文件：保持现有右下角图标按需展开（已是按需形态，不动）
- CSS：`.app` 增加 `light`/`project` 双态 class（state 驱动），复用已有响应式断点（`has-ctx`/`browser-mode` 收拢逻辑）

### 5.2 会话模型：隐式 cwd

- 新会话不问项目：创建即进入聊天，会话隐式绑定**当前工作目录**（ZCode workspace 语义； OrchDesk 已有 `sessionCwd`/`applySessionCwd` 机制，复用之）
- 会话列表按目录分组展示（目录名即组名）；"项目/任务"分组从必填前置结构降级为**可选的归档整理**（侧栏底部入口 + 设置页），老用户习惯不变
- 分叉/回放/事件流：能力保留，入口随会话就绪度出现（有分叉才显示）

### 5.3 模型：内嵌配置（A）

- composer 旁常驻**模型 chip**（当前默认模型 + 状态点）：
  - 启动时探测本机 Ollama（`http://127.0.0.1:11434/api/tags`，主进程代查）→ 有模型则 chip 显示"Ollama · 就绪"，**一键可聊，零配置**
  - 无 Ollama → chip 显示"未配置"，点击弹出**内嵌预设面板**：models.dev 预设搜索（已建成）+ 粘 KEY 两步完成（自动拉取模型、默认全选——复用已建成的 `model-catalog` 链路），**不跳设置页、不填 URL/协议**
  - 两者都无 → 提供**演示模式**（echo Agent，回复回显+工具模拟），用户可逛完所有 UI，随时替换真模型
- 设置页"模型管理"保留为完整形态（多提供商/编辑/测试/协议选择），轻模式用户不需要先访问它

### 5.4 风控：默认最小集 + 友好询问

- 轻模式默认档 = "默认安全"（A1 修复后形态：意图门仅拦真危险模式；L3/L4 执行弹窗保留）
- **网络白名单空名单的静默全拒改为首次询问**：web_fetch/browser_open 命中空名单时，弹出"该操作需要访问外部域名 X：允许一次 / 记住该域名 / 拒绝"——fail-closed 底线不变（无应答方时仍拒绝），但用户不再面对"没反应"
- 补偿层/L0-L4/三模式切换入口：收进入设置页"授权"区，首日不曝光

## 6. 项目模式（按需深化）

- 触发（§4）：建项目/任务、多步 orch-plan、专家团引用
- 展开内容：右栏任务监控常驻（可收起）、专家团派发入口、分叉按钮、项目切换器
- 回落：用户可手动切回轻模式（导航抽屉顶栏切换）；模式选择记忆
- **所有现有能力原样保留**——项目模式即今天的完整体验，只是不再默认

## 7. 第二阶段：原有功能 UX 调研优化

- 方法：启发式评估（Nielsen 10）+ 认知负荷 checklist（沿用本会话评审框架），逐 surface 走查，产出 P0-P3 问题清单
- Surface 清单（按优先级）：
  1. 会话页/欢迎页（简化后复评）
  2. 插件页 7 分区（内置/市场/技能/专家/连接器/MCP/临时插件——IA 与徽章密度）
  3. 设置页 7 分区（模型/凭据/沙箱与授权/提示词/桌面集成/数据目录/关于——分区与风控文案）
  4. 任务监控/分叉回放（编排可视化的可读性）
  5. 文件面板/终端/浏览器面板（按需展开后的状态反馈）
  6. 授权流（三模式卡片/L0-L4/白名单/补偿层确认的话术与层级）
- 交织方式：被第一阶段触及的表面随阶段复评；未触及的进 backlog 按序实施

## 8. 技术要点

- **渲染层 only**：主进程/插件/风控/模型链路/vendor 全部复用；`sessionCwd`、`model-catalog`、`orchdesk:ollama-probe`（新增小 IPC）为仅有的主进程触点
- app.js 已 4100+ 行：借简化之机拆出 `layout.js`（布局/导航/面板按需逻辑）、`welcome.js`（欢迎页+模型 chip+演示模式），会话/设置/插件维持 actions 化现状——止住膨胀，不再扩大
- 布局双态 class + state 驱动，复用已有响应式断点
- Ollama 探测与 models.dev 目录均走主进程（CSP `default-src 'self'` 不变）

## 9. 分期

| 阶段 | 内容 | 出口标准 |
|------|------|----------|
| P1 轻模式骨架 | 单栏布局双态、导航收拢、任务监控回合中浮出、隐式 cwd 会话 | 新用户首屏只有列表+输入框；e2e 全绿 |
| P2 模型内嵌 | 模型 chip、Ollama 自发现、预设面板两步配、演示模式 | 零配置 Ollama 用户打开即聊；无模型用户 ≤3 次点击可聊 |
| P3 项目模式 | 触发条件、重形态展开/回落、模式记忆 | 编排用户路径不变，轻用户不被曝光 |
| P4 UX 调研优化 | §7 清单逐 surface 评估与修复 | 每个 surface 有问题清单与修复记录 |

## 10. 风险

- **渲染层大改的回归面**：布局/导航/会话创建是最高频路径——靠 e2e（262 项）兜底 + 每个 P 阶段后全链验证；P1 先做双态并存（light 默认、project 可用），再逐项迁移，避免大 bang 切换
- **隐式 cwd 与项目数据的兼容**：老数据（显式项目结构）必须在轻模式正确显示（按目录分组时归档项目单列），迁移只读不改写
- **白名单首次询问**不破坏 fail-closed：无 GUI 应答方（headless/verify）仍硬拒，仅 GUI 场景多一次授权交互
