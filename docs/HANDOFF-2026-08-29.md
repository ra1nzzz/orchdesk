## 任务清单（按优先级）

### T1：Agent Runtime 工具调用稳定化（BUG-014）

**目标**：用户发送 "复用本地鉴权，检查与远程 GITHUB 版本差异" 时，Agent 应该：
1. 解析出需要执行的工具（如 `shell_command`）
2. 执行工具
3. 把结果汇总回复给用户

**当前状态**：
- 工具调用正则已从 `<\/?>` 改为 `<\/tool>`，正则匹配 OK
- 但模型回传的格式有多种变体（function-call JSON / 自定义 XML / 纯文本），当前只处理了 XML 格式
- 工具结果用 `role: 'system'` 回传（不合规）
- 详见 `docs/KNOWN-ISSUES.md` 第二节分析

**修复方案（双模式适配）**：

1. 在 `callModel()` / `callOpenAICompatible()` 中保留 tool_choice 传递
2. `runAgentTurn()` 中**优先解析 `choice.message.tool_calls`**（OpenAI native format）
3. 如果模型没有返回 `tool_calls`，fallback 到正则解析 `<tool:name>args</tool>`
4. 工具结果用 `{role: 'tool', content: result}` 回传（不再用 `role: 'system'`）
5. 对话历史中加入 tool call + result 对时使用正确的 role

**关键文件**：
- `apps/desktop/main.ts` L353-446（runAgentTurn 主循环）
- `apps/desktop/main.ts` L150-210（callOpenAICompatible）
- `apps/desktop/main.ts` L306-347（TOOL_DEFS）
- `apps/desktop/main.ts` L254-303（executeTool）

**验证方式**：不用等 GUI，直接用 node 脚本调用主进程函数，或用 E2E (`node e2e-fix-verify.cjs`)。注意 E2E mock 需要返回带 `tool_calls` 的格式。

### T2：数据持久化路径隔离（BUG-013）

**目标**：不同安装形态下数据互通。

**当前状态**：
- 会话存 `app.getPath('userData') + '/orchdesk-sessions.json'`
- 模型配置存 `app.getPath('userData') + '/models.json'`
- `userData` 路径：
  - dev：`<repo>/apps/desktop/`
  - portable：`<exe旁>/orchdesk-data/`（实际值取决于 electron-builder）
  - NSIS：`%APPDATA%\OrchDesk\`

**修复方案（短期 + 长期）**：

短期：
- 在 `main.ts` 初始化时添加路径迁移逻辑
- 扫描多个可能的 userData 位置，合并数据到当前路径
- 至少保底：portable 模式下在 exe 同目录放数据，开发模式在 repo 内放数据

长期（建议但不紧急）：
- 侧栏添加「导出 / 导入」JSON 功能
- 升级时自动备份旧数据到 `snapshots/` 目录

### 关键架构约束（不可违反）

1. **渲染层禁止直接调用 `require()` / Node API** — 必须通过 `window.orchdesk` contextBridge
2. **工具执行只在主进程** — executeTool() 在 main.ts 中
3. **会话持久化在主进程** — 渲染层通过 `orchdesk:persist-sessions` IPC
4. **会话存储是内存 store + JSON 文件双写** — 不是浏览器 LocalStorage
5. **TypeScript strict 模式** — 不能有 `any` 绕过编译
