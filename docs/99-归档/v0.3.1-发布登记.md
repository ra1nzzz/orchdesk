## 修复内容

### BUG-014 Agent Runtime 工具调用稳定化（核心）

真正的根因：旧 `runAgentTurn` 把工具参数构造成 `{ input: "<args 原文>" }`，
而 `executeTool` 读的是 `args.path` / `args.command`，**工具必然执行失败**。
前三轮修复都聚焦「模型输出格式不匹配」，方向偏了。

1. 新增纯逻辑模块 `apps/desktop/agent-runtime.ts`（零 electron 依赖、可 node 直测）
2. `callModel` 返回结构化 `ModelReply`，消除「tool_calls → `<tool:>` 文本 → 正则解码」往返
3. 原生 `tool_calls` 全部执行（旧实现只取 `[0]`），统一 OpenAI / Ollama / 摊平三种形态
4. 工具结果回传合规：原生 `role:'tool'` + `tool_call_id`；文本兜底 `role:'user'`；不再用 `role:'system'`
5. 文本兜底支持 4 种模型自发格式 + 缺闭合标签容错 + 去重 + 未知工具名过滤
6. 网关拒 tools（400/404/415/422）逐级降级，成功后转文本兜底

### BUG-013 数据持久化路径隔离

`dataDir()` = `ORCHDESK_HOME` > 便携模式（exe 同目录 `orchdesk-data`）> `%APPDATA%/OrchDesk`。
NSIS 的 userData 即 `%APPDATA%\OrchDesk`，故 **portable 与 NSIS 共用同一目录**。
`migrateLegacyData()` 启动时从全部历史候选目录合并（只补齐不覆盖）。

### BUG-015 / BUG-016

- 未选模型时先重试自动选择，仍为空则跳转「设置 → 模型管理」（不再是死胡同）
- 打包前 `kill-running.cjs` 结束 OrchDesk.exe 并等 1.5s 释放句柄，解决 EBUSY
